# เคสทดสอบ 3 OA — ตาม workflow, ตามฟังก์ชัน, และ UI/UX

เขียน 4 ก.ย. 2569 หลังแผน `docs/PLAN_3OA.md` ข้อ B1–B8 ขึ้น dev ครบ (commit `f9d417a` + `phase20-i18n-v1`)
ใช้ทดสอบกับ OA จริง 3 ตัว (Sale = เขียว, Tech = น้ำเงิน, CS/ลูกค้า = ส้ม) และหน้าจอ LIFF ของแต่ละ OA

วิธีอ่าน: แต่ละเคสมี **เตรียม → ทำ → ต้องเห็น** ช่อง "ผล" ให้กรอก ✅ / ❌ + หมายเหตุ
รหัสเคส: `X-` ข้ามทั้ง 3 OA (end-to-end) · `S-` Sale OA · `T-` Tech OA · `C-` CS OA · `U-` UI/UX (ตามสกิล ui-ux-pro-max)

บัญชีที่ต้องมีก่อนเริ่ม: เจ้าของร้าน 1 (Sale OA), ช่าง 2 คน (Tech OA, คนหนึ่งเป็นหัวหน้าทีม), ลูกค้า 2 คน (CS OA) —
ลูกค้าคนที่ 2 ใช้ทดสอบ "ไม่เห็นของคนอื่น" ทุกที่ที่ระบุ

## 1. Workflow ข้ามทั้ง 3 OA (end-to-end)

| รหัส | ชื่อเคส | เตรียม | ทำ (ตามลำดับ) | ต้องเห็น | ผล |
|---|---|---|---|---|---|
| X-01 | วงจรซ่อมเต็ม: ลงทะเบียน → แจ้งซ่อม → มอบหมาย → รับ → เช็คอิน → ปิดงาน → อนุมัติ → ประเมิน | ร้านบันทึกเครื่อง (Sale: `ลงทะเบียนสินค้า SN-X1 แอร์ ให้ สมชาย`) | 1) CS OA: `ลงทะเบียนสินค้า SN-X1` 2) CS: `แอร์ไม่เย็น` → ที่อยู่ → นัด 3) Sale ได้ LINE "แจ้งซ่อมใหม่" → `มอบหมาย T-… ให้ ช่างA` 4) Tech OA (ช่างA) ได้ LINE → `รับงาน T-…` 5) `เช็คอิน` 6) `ปิดงาน` + ตอบ 3 ข้อ 7) Sale: `อนุมัติ SR-…` 8) CS ได้ปุ่มคะแนน → กด 3 | ทุกขั้นได้ข้อความยืนยันเป็นเลขงานเดียวกัน · ขั้น 3 มอบหมายไม่ผ่านถ้าขาดชื่อ/เบอร์/ที่อยู่/นัด (บอกว่าขาดอะไร) · ขั้น 6 ปิดงานไม่ได้ก่อนเช็คอิน · ขั้น 7 ได้ PDF ลิงก์ (มีลายเซ็นถ้าตั้งไว้ + รูปหน้างานถ้าส่ง) · ขั้น 8 "ขอบคุณ" และงานเป็นเสร็จ | |
| X-02 | ทีมช่าง: มอบหมายให้ทีม → หัวหน้ารับแทนทีม → สมาชิกรับ | ทีม "แอร์" มีหัวหน้า (ช่างA) + สมาชิก (ช่างB) | 1) Sale: `มอบหมาย T-… ให้ทีม แอร์` 2) ช่างA: `รับงาน T-…` 3) ช่างB: `งานของทีม` → `รับงาน T-…` | ขั้น 2 ช่างB ได้ LINE "หัวหน้าทีมรับงาน … ใครไปพิมพ์ รับงาน" · ขั้น 3 งานเป็นของช่างB สถานะ assigned · Sale เห็นชื่อช่างB ในหน้างานซ่อม | |
| X-03 | ปฏิเสธงาน ไม่ auto-reassign | งานมอบหมายให้ช่างA แล้ว | ช่างA: `ปฏิเสธงาน T-… ติดงานอื่น` | Sale ได้ LINE ว่าปฏิเสธ + เหตุผล · งานกลับเป็น open ในหน้างานซ่อม · ช่างB **ไม่ได้** รับอัตโนมัติ | |
| X-04 | ลูกค้าคุยกับร้าน (Phase 15) | ลูกค้าผูกร้านแล้ว | 1) CS: `คุยกับร้าน ราคาแอร์ 12000 BTU` 2) Sale: หน้าจอ > แชทลูกค้า → เปิด → พิมพ์ตอบ → ส่ง 3) CS: `แอร์ไม่เย็น ซ่อมได้ไหม` 4) CS: `งานของฉัน` 5) CS: `จบการสนทนา` | 1) CS ได้ "เปิดการสนทนากับ <ร้าน>"; เจ้าของ+CS ได้ LINE 💬 พร้อมข้อความแรก 2) CS ได้ "💬 <ร้าน>: …" ใน LINE; รายการเป็น "กำลังคุย" ของคนที่ตอบ 3) ได้ "ส่งถึงร้านแล้ว" และ **ไม่** เปิดงานซ่อม 4) ยังตอบสถานะงานปกติ 5) ปิด; เจ้าของการสนทนาเห็นในแดชบอร์ด | |
| X-05 | SLA แชท เตือนครั้งเดียว | ตั้ง license setting `chat_sla_minutes` = 1 | CS: `คุยกับร้าน` → รอ >1 นาที → Sale เปิดหน้าแชทลูกค้า (เป็นตัว tick) → เปิดซ้ำอีกครั้ง | ครั้งแรก: เจ้าของการสนทนา (หรือทุกคนถ้ายังไม่มี) ได้ LINE "⏰ … ยังไม่ได้รับคำตอบ" · เปิดซ้ำ: **ไม่** เตือนซ้ำ | |
| X-06 | แชทปิดเอง (timeout) | ตั้ง `chat_timeout_minutes` = 1 | เปิดแชท → ไม่พิมพ์ >1 นาที → Sale เปิดหน้าแชทลูกค้า | สถานะ "ปิดอัตโนมัติ" · CS ได้ LINE "ปิดอัตโนมัติ … พิมพ์ คุยกับร้าน ได้อีก" · หลังจากนั้นข้อความอิสระของลูกค้ากลับไปเป็นแจ้งซ่อมตามปกติ | |
| X-07 | storefront → lead → เจ้าของรู้ | ร้านมีสินค้า ≥2 (Sale: `สร้างสินค้า …`) | CS: `สินค้าทั้งหมด` → `1` | รายการมีสินค้าจากทุกร้าน (ชื่อ · ร้าน · ราคา) · เลือกแล้ว "ร้าน … จะติดต่อกลับ" · เจ้าของได้ LINE "ลูกค้าสนใจสินค้า" · Sale `รายชื่อลูกค้า` มี lead ใหม่ | |
| X-08 | ลูกค้าใหม่ผูกร้าน auto-accept | เจ้าของ: `ตั้งค่ารับลูกค้าใหม่อัตโนมัติ เปิด`; ลูกค้าคนที่ 2 มีชื่อ+เบอร์ในโปรไฟล์ | ลูกค้า 2 ผูกร้านด้วย S/N หรือชื่อร้าน | เจ้าของได้ LINE "เพิ่มเข้ารายชื่อลูกค้าให้แล้ว" · `รายชื่อลูกค้า` มีชื่อทันที · ตั้ง "ปิด" แล้วทำซ้ำ → ได้ LINE พร้อมคำสั่ง "สร้างลูกค้า …" แทน | |
| X-09 | ภาษาของผู้รับ (Phase 20) | เจ้าของ: `english`; ลูกค้า: ไทย | ลูกค้าแจ้งซ่อม / กดสนใจ / คุยกับร้าน | LINE ที่เจ้าของได้รับเป็นอังกฤษทุกฉบับ · เจ้าของ `ภาษาไทย` → ฉบับถัดไปเป็นไทย · ลูกค้าไม่ได้รับผลกระทบ | |
| X-10 | รูปแบบวันที่/เขตเวลา (16.3) | — | Tech: `รูปแบบวันที่ yyyy-mm-dd` → `งานของฉัน` · `เขตเวลา Asia/Tokyo` → งานที่นัดพรุ่งนี้ | วันที่ในทุกข้อความเป็น 2569-09-05 · หลังเปลี่ยนเขตเวลา "วันนี้/พรุ่งนี้" คำนวณตามโตเกียว · ค่าผิด (`เขตเวลา Mars/X`) ถูกปฏิเสธพร้อมตัวอย่าง | |
| X-11 | หลายร้าน (MULTIPLE) | ลูกค้าคนเดียวผูก 2 ร้าน | CS: พิมพ์อะไรก็ได้ → `เปลี่ยนร้าน` → เลือก · home: สวิตช์ร้าน | ไม่วนถามร้านซ้ำทุกข้อความ · เลือกแล้วจำ 90 วัน · งาน/สินค้า/ประวัติเปลี่ยนตามร้านที่เลือกทั้งแชทและ home | |
| X-12 | รูปหน้างานและลายเซ็นขึ้น PDF | ช่างเช็คอินแล้ว; เจ้าของวาดลายเซ็นที่ ข้อมูลของฉัน | ช่างส่งรูป 2 รูปในแชท (หรือปุ่มบน home) → ปิดงาน → เจ้าของอนุมัติ → เปิด PDF | ช่างได้ "แนบรูปกับงาน T-… แล้ว (n รูป)" · PDF มีหัวข้อรูปหน้างาน (สูงสุด 4) + ลายเซ็นผู้อนุมัติ · หน้ารายงานของ Sale เห็นแถบรูป | |

## 2. Sale OA (เขียว) — ตามฟังก์ชัน

### 2.1 แชท

| รหัส | ฟังก์ชัน | ทำ | ต้องเห็น | ผล |
|---|---|---|---|---|
| S-01 | ต้อนรับ | add เพื่อน / บล็อกแล้ว add ใหม่ | ข้อความต้อนรับ + quick reply (งานวันนี้ / รายชื่อลูกค้า / วิธีใช้) ทันที | |
| S-02 | ตั้งร้าน | `สร้างบริษัท …` (ครั้งแรก) → `ข้อมูลร้าน` → `รหัสร้าน` | ได้รหัสร้านที่ลูกค้าใช้ผูก · `ข้อมูลร้านค้า` / `ขอข้อมูลร้านค้า` / `รหัสร้านค้า` ทุกคำตอบเหมือนกัน **ไม่** ขึ้นรายการสิทธิ์ | |

| S-07 | CRM | `รายชื่อลูกค้า` · `สร้างลูกค้า สมหญิง 0812345678` · `ยืนยันลูกค้าสมหญิง` · `สร้างดีล …` · `ออกใบเสนอราคา Q-…` · `งานวันนี้` · `เตือน D-… พรุ่งนี้` | lead→contact ได้ · ใบเสนอราคา PDF เปิดได้ · งานวันนี้รวมนัด+เตือน | |

## 3. Tech OA (น้ำเงิน) — ตามฟังก์ชัน

| รหัส | ฟังก์ชัน | ทำ | ต้องเห็น | ผล |
|---|---|---|---|---|
